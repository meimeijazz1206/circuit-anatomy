# 賽道解剖 Circuit Anatomy

用真實座標做的 3D 賽道導覽。

- `index.html`：**2026 賽季首頁**，海報風（紅→黑→黃三段）。
  - 封面：最新建好的賽道當主打、下一站貼紙、開賽倒數
  - 賽程：23 站兩欄列表，建好的整列黃底可點，跑完的站顯示冠軍
  - 名次：每站前三名，可展開前 10 名
  - 資料邏輯在 `season.js`（下一站、完賽數都依當天日期自動算）
- `drafts/`：首頁三個方向的草稿（A 海報／B 雜誌／C 計時塔），留作參考
- `suzuka.html`、`monza.html`：單條賽道頁。

目前建好：**鈴鹿**（R03）、**Monza**（R13）、**Sepang**（R16，巴林站移師馬來西亞）、**新加坡**（R17）。
另有 **巴林 Sakhir** 的賽道頁（`bahrain.html`），今年沒在那裡比賽，首頁不連結。

兩條賽道用同一套程式，但**視覺語言不同**——因為它們難的地方不一樣。

| | 鈴鹿 | Monza |
|---|---|---|
| 故事 | 高低差與節奏 | 速度與煞車 |
| 主視覺 | 立體高程＋側裙 | 加速／彎中／煞車三色帶 |
| 下方剖面 | 高程剖面 | 速度剖面＋煞車區 |
| 實測全長 | 5,798 m（官方 5,807，−0.16%） | 5,789 m（官方 5,793，−0.07%） |
| 高程 | 40.5 m，國土地理院 DEM | 攤平，見下方「為什麼 Monza 是平的」 |

## 共通功能

- **彎角卡**：每條三張，講「為什麼難」與「從哪裡看」。點卡片會飛過去並標出該段落。
- **看台視角**：移到彎外側約 130–280 m、高 24 m 的位置。有高程的賽道會自動把高程放大降到 ×1.5，因為觀眾看到的是真實比例。
- **車載視角**：沿中心線跑一圈，速度依模型值，所以節奏接近真實（鈴鹿約 97 秒、Monza 約 87 秒）。
- **剖面圖**：與車載位置同步。
- **右上角小地圖**：畫出賽道輪廓、目前位置、已跑過的部分，並顯示**現在在第幾號彎**（T1–T18 / T1–T11）、路段名稱，以及**下一個彎還有多遠**。車載視角只看得到眼前幾十公尺，沒有這個就不知道自己在哪。

彎號不是自動偵測的——自動偵測只認得出鈴鹿 16 個、Monza 7 個，因為它切不開複合彎裡的每個彎心。所以 `prepare_web.py` 的 `TURN_GROUPS` 由人工指定「哪一段裡有哪幾號彎」，程式再把該段平均切開、各取曲率最大的點當彎心。

車載視角會自動做兩件事：把高程放大降回 ×1（×5 的話 S 字彎會變成一面牆），以及把 Monza 的狀態色帶收起來、路面換回柏油色（那是圖解用的顏色，從駕駛座看只會擋住視線）。

## 資料怎麼來的

```bash
python3 build_track.py  monza     # Overpass 原始資料 → 串成封閉迴圈 → 投影成公尺座標
python3 fetch_elev.py   monza     # 取海拔（日本用國土地理院，其他用 open-meteo）
python3 prepare_web.py  monza     # 重取樣、平滑、算里程／曲率／速度 → tracks/monza.js
```

`build_track.py` 從主直線的 way 出發，沿端點相接走回原點；卡丁車道、舊高速環道、Pit Lane 等在 `TRACKS` 設定裡排除。**全長對得上官方數字，就是串對了**——這是唯一可靠的驗收標準。

## 速度是怎麼算的（不是遙測）

`prepare_web.py` 由曲率推算，不是實測資料：

1. 每點的過彎速度上限 `v² k = A_LAT0 + A_LAT_V · v²`——橫向抓地力隨速度上升，因為下壓力正比於 v²。這是高速彎能全油門通過的原因。
2. 前後掃描套用加速與煞車極限，環狀迭代三次。
3. 分類每個點是誰在限制車速：還在減速 = 煞車區；離抓地力上限還有餘裕 = 加速區；貼著上限 = 彎中。

**對得上的**：極速 346 / 317 km/h、最慢點的位置、單圈節奏（比實際慢約 8%，兩條一致）。

**刻意不宣稱的**：官方那種「全油門百分比」。模型分不出油門踏板開度，硬報一個數字會是錯的。所以面板上寫的是「時速 300 以上佔一圈時間」——Monza 34%、鈴鹿 18%，這是模型真的算得出來、也真的能代表兩條賽道差異的數字。

## 為什麼 Monza 是平的

Monza 實際高低差只有約 10 m。用全球 DEM（open-meteo，約 90 m 解析度）量到的是 **26 m**——多出來的是公園的樹冠與建物，不是賽道。

與其畫假的起伏，不如攤平，改用速度／煞車當視覺語言。這也是這條賽道真正的故事。

**結論給下一條賽道**：全球 DEM 只在高低差夠大的賽道（Spa、Interlagos、Austin）撐得住。平坦賽道要嘛換高精度在地 DEM，要嘛就別畫高程。

### 做新賽道的流程

```bash
python3 build_track.py <circuitId>     # build_track.py 的 TRACKS 先加設定
python3 fetch_elev.py  <circuitId>     # 需要高程時才跑
python3 prepare_web.py <circuitId>     # CFG 與 TURN_GROUPS 先加設定
python3 make_outlines.py               # 首頁縮圖
python3 make_calendar.py               # BUILT 加上這條，首頁就會亮
```

再補：`tracks/<id>_corners.js`（三張彎角卡）、`<id>.html`（複製 suzuka.html 改 data-track）、`season.js` 的 STATS 與 LEDE。

**彎角卡的每一句都要對過資料**：數字一律從 `tracks/<id>.js` 查，查不到的只寫公開來源確認過的事。

## 街道賽學到的事

- **單行道方向不能拿來判斷比賽方向**：新加坡平日的單行道，剛好跟比賽方向相反。方向改用 `find_loop.py` 的 `DIRECTION` 表。
- **有些賽道路段平常是人行道**（新加坡的 Fullerton Road）：circuit relation 的成員一律收，不看道路等級。
- **OSM 的配置名稱會標錯**：銀石叫「International」的 relation 其實是完整的 GP 路線。要看彎名順序，不要看 relation 名稱。
- **不能用「含 Pit 字樣」來排除維修區**：銀石的 National Pit Straight 就是賽道的一部分。

## 巴林學到的三件事

1. **Overpass 現在會擋沒有身分的請求**（HTTP 406）。`curl` 要加 `-A "circuit-anatomy/1.0 (personal hobby project)"`，而且伺服器常忙，要重試或換鏡像站。
2. **多種配置疊在一起時，別用貪婪串接**。巴林有 GP、Inner、Outer、Endurance 等六種配置共用路段，改用 OSM 的「Bahrain Grand Prix Circuit」relation（284538）給的路段順序，`build_track.py` 裡用 `order` 指定。全長 5,412.3 m，官方 5,412 m。
3. **全球 DEM 能不能用，看賽道周圍有沒有東西擋**。巴林在沙漠，DEM 量到 19 m、公開資料約 17 m——可信，所以畫高程；Monza 在公園裡，樹冠讓 DEM 量到 26 m、實際只有約 10 m——不可信，所以攤平。

另外：OSM 在巴林沒有彎名，3D 標籤改用彎號（`META.tagTurns`），路段名稱由 `turnNames`、`straights` 人工補。起跑線也沒標，用維修區中點推估（`start_at`）。

## 常設賽道 12 條學到的事（2026-09-30）

- **整圈是一條閉合的 way 時，solve 找不到迴圈**（上海、加拿大）：體檢 `best_m` 是 None，其實資料很乾淨。看最長的那條 way 首尾是否閉合，用 `order` 模式直接指定。
- **relation 的成員清單會有重複項目**（銀石）：去重後照順序走一圈，並用全長（誤差 < 0.1%）確認沒走錯。
- **`start_pit: 'auto'` 在維修區被切成好幾段時會選錯**（阿布達比選到 73 m 的連接線、摩納哥被投影到別的位置）：改用維修區兩端沿賽道的中點，算出經緯度寫在 `prepare_web.py` CFG 的 `start_at`。
- **彎號一定要找 turn-by-turn 當錨點**，再用「導覽給的左右總數」當約束（銀石 10 右 8 左、奧地利 7 右 3 左、卡達 6 左 10 右）。曲率峰值數量常常對不上官方彎數：一個複合彎會有好幾個峰，快速微彎又會低於門檻。
- **導覽也會互相矛盾**（澳洲的 14／16 彎編號、摩納哥的名稱）：選明確標示現行編號、又跟曲率對得上的那一份，並把不確定的彎寫進 `hint`。
- **Overpass／open-meteo 會限流**（HTTP 429）：高程請求失敗就晚點重試。
- **DEM 判斷**：對得上（±10% 內，且最高、最低點位置也吻合）才畫立體——Spa、Interlagos、奧地利。匈牙利（+17%，最低點位置不對）、摩納哥（+40%，山坡建築）、街道賽都攤平。

## 其他已知限制

- **鈴鹿 8 字交叉的橋**：DEM 是地表模型，抓不到橋下淨空（實測只差 2 m）。`tracks/suzuka_corners.js` 的 `crossover` 用 5 m 做視覺補正，不是實測值。
- **賽道寬度是示意值**（直線 15 m、彎道 12 m），OSM 沒有寬度資料。Monza 的三色帶更寬（半寬 22 m），純粹是為了在全景看得見。
- **傾斜角（banking）沒有資料**，路面一律水平。
- **彎號的分組是人工指定的**（見上），只有彎心位置是算出來的。

## 要加第三條賽道

1. `build_track.py` 的 `TRACKS` 加一組設定（Overpass 查詢、起點 way、要排除的 way、官方長度）。
2. `fetch_elev.py` 的 `SOURCE` 指定高程來源；日本以外目前只有 open-meteo。
3. `prepare_web.py` 的 `CFG` 設 `v_top`、`flatten`、`profile`。
4. `prepare_web.py` 的 `TURN_GROUPS` 指定官方彎號分組。
5. 新增 `tracks/<id>_corners.js`（META ＋三張彎角卡），複製 `suzuka.html` 改 `data-track` 與 `<title>`。
6. 跑 `python3 make_outlines.py` 產生首頁縮圖，並在 `calendar.js` 把那一站的 `track` 從 `null` 改成賽道 id。

## 授權與立場

賽道名稱與彎名為地理與歷史名稱。本頁不使用任何賽事、車隊或車手的商標與影像，與任何賽事主辦單位無關。速度為模型推算，非官方數據。
